# Windows UI·안정성 개선 작업

기준: 2026-10-27의 macOS 소스와 Windows 0.1.0.6. 계정·오늘 날짜·시간대·게시일 범위·누적 지표·증가량·RT 판정은 보존한다.

## 범위와 완료 조건

- Fluent 테마와 공통 색상·서체·간격. 고정된 요약, 기간 탭, 목록만 스크롤, 그룹별 설정.
- 실제 Windows에서 밝음/어두움, 긴 ko/en/ja 문구, 배율, 키보드 조작, 보드 크기 확인.
- macOS의 탐색 제한 시간·재시도·인증 입력 보호에 대응하는 Windows 회귀 시험.
- 같은 범위의 갱신 중 이전 값을 유지하되 마지막 확인 시각/갱신 상태를 명시. 다른 계정·기간·날짜의 값은 표시 금지.
- 새 MSIX 업데이트 후 로그인·설정 유지. 임시 인증서와 개발자 모드는 승인된 시험 범위에서만 사용 후 복구.

## 동시성·저장 변경 위험과 검증

| 경로 | 위험 | 선택한 처리와 검증 |
| --- | --- | --- |
| 멈춘 WebView2 응답 | 계속 대기하여 자동 복구 중단 | 각 읽기와 수집 전체에 제한 시간. 미완료 Promise/취소 시험 |
| 기간 변경·절전 중 진행 작업 | 이전 결과가 새 범위를 덮음 | 취소와 generation 검증을 함께 유지. 마지막 범위로 후속 작업 예약 |
| 갱신 중 기존 목록 유지 | 다른 범위의 값을 혼동 | 게시물 계정·기간·날짜·시간대를 명시한 scope 저장. 잘못된 scope는 숨김 |
| 초기화 중 종료 | WebView 폐기가 초기화 continuation을 즉시 실행해 목록 변경 | 소유 목록을 먼저 비우고 복사한 목록을 정리. 초기화 중 종료·중복 폐기 시험 |
| UI 갱신 | 입력 중 선택·포커스·스크롤 손실 | 영구 컨트롤과 게시물 ID별 행을 갱신. 실제 키보드/포커스 시험 |
| DPI·모니터 복구 | 좌표 단위 혼합으로 화면 밖 이동 | 실제 창의 물리 좌표 기준 복구 후 WPF 위치 저장. 분리 상황 모사 시험 |

공개 서명·Store 공개·Windows 자동 업데이트 피드는 배포 작업이다. macOS의 Sparkle 공개 배포와 동등하다고 주장하지 않는다. 물리적 절전·장기 실행 신뢰성은 관찰한 범위를 따로 기록한다.

## macOS와 비교한 구현·검증 범위

| 항목 | Windows 구현 및 확인 |
| --- | --- |
| 오늘 노출, 게시물 기간과 누적 지표 | 같은 검증 규칙. 실제 계정 수집 및 보드 기간 변경 |
| 증가 순위, RT 급증 판정 | 계정·기간·날짜 변경 시 기준 초기화, 정확한 카운트·관측 간격·재알림 제한 시험 |
| 연결과 인증 입력 보호 | 격리된 WebView2, 입력 중 복구 이동 차단, 로그아웃·업데이트 유지 시험 |
| 지연·실패 복구 | 읽기 8초·탐색 45초·전체 100초, 제한된 재시도, 실패 렌더러 재생성 |
| 중복 갱신·늦은 결과 | 단일 수집, 마지막 기간 요청 처리, 취소 결과 거부, 종료 중 초기화 재진입 정리 |
| 화면과 접근성 | 두 위젯, ko/en/ja, 시스템 색상, 키보드·포커스·스크롤, 확대 배치, 화면 밖 위치 복구 |
| 로그인 시 시작 | 패키지 StartupTask의 상태를 읽고 사용자 선택으로 변경. 실제 Windows 로그아웃·재로그인 후 자동 표시와 X 세션 유지 확인. [후속 시험](VALIDATION-STARTUP.md) |
| 공개 자동 업데이트 | Windows 배포 피드 미구성. 개발 MSIX의 로그인·설정 보존 업데이트만 확인 |

WPF의 첫 하드웨어 렌더링 화면이 비거나 일부만 보이고 크기를 바꾸면 복구되는 현상을 설치본에서 발견했다. 작은 위젯·설정 창의 HwndTarget을 SoftwareOnly로 설정한다. WebView2는 별도 렌더러를 유지한다. 이는 해당 PC의 관찰을 근거로 한 호환성 조치이며 특정 GPU 드라이버가 원인이라고 단정하지 않는다. [Microsoft의 렌더링 모드 설명](https://learn.microsoft.com/en-us/dotnet/api/system.windows.media.renderoptions.processrendermode?view=windowsdesktop-10.0).

배율 시험은 WPF LayoutTransform으로 100·150·200%를 모사한다. 실제 PC 배율은 96 DPI다. 고대비는 선택 배경·문자 색상 쌍을 시험하며 OS 전체 고대비 설정은 변경하지 않는다. 절전·네트워크 복구는 동일 핸들러에 재현 입력을 주어 검증한다. 실제 절전, 물리적인 모니터 분리, 장기간 연속 운용까지 검증한 것으로 해석하지 않는다.
